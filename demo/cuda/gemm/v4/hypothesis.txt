Hypothesis: Increase tile size from 16 to 32 while keeping block size at 16x16 to halve
            K-loop iterations and barrier calls naturally
Rationale : v3 NCU Barrier stall=5.76 still dominant. Tile fusion (v2/v3) reduces barriers
            at the cost of more shared memory and complex cooperative loading.
            TILE=32 with 16x16 threads halves K iterations (64→32) and barriers (128→64)
            naturally, without the multi-tile loading complexity of v2/v3.
            Each thread loads 4 A + 4 B values cooperatively into 32x32 shared tiles.
            2x32x32x4 = 8KB shared memory (same as v3). Occ stays at 95%.
            Experience log tested tile 16→32 WITH 32x32 threads and regressed due to
            occupancy collapse; this approach keeps 16x16 threads, avoiding that pitfall.
Expected  : Barrier stall ↓ 10-15%, code simpler with fewer branch instructions,
            latency ↓ 2-5%. Risk: 4 loads per tile may increase LSU contention.
